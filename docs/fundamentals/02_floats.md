# 02. 浮動小数点数

```bash
cargo run -p fundamentals --example floats
```

## 1. 小数をどう表しているのか（IEEE 754）

`f64` は 64 ビットを3つの部分に分けて小数を表します。

```
[符号 1bit][指数 11bit][仮数 52bit]
  値 = (-1)^符号 × 1.仮数 × 2^(指数 - 1023)
```

10進数の「指数表記」（6.02 × 10²³）を、2進数でやっているものです。
- **仮数**が精度（有効桁数）を決めます。`f64` はおよそ10進数で15〜17桁です
- **指数**が大きさの範囲を決めます。とても大きな数から、とても小さな数まで表せます

範囲が広い代わりに、**精度は有限**です。ここから2つの問題が生まれます。

## 2. 問題1: 0.1 を正確に表せない

10進数で 1/3 = 0.333... が割り切れないのと同じように、2進数では 0.1 が割り切れません。

```
0.1 を精度20桁で = 0.10000000000000000555
0.1 + 0.2        = 0.30000000000000004
0.1 + 0.2 == 0.3 → false
```

**教訓**
- 浮動小数点数同士を `==` で比べない。差が十分小さいかで比べる
- **お金を `f64` で扱わない**。整数で「円」や「セント」の単位で持つか、`rust_decimal` のような10進数の型を使う

## 3. 問題2: 大きな数では整数すら正確に表せない

仮数が 52 ビットしかないので、2⁵³ を超えると 1 刻みの整数が表せなくなります。

```
2^53     = 9007199254740992
2^53 + 1 = 9007199254740992  ← 1 が消えた
```

JavaScript の数値は全て `f64` です。そのため JS で大きな ID（Twitter の ID など）を扱うと桁が壊れる問題が実際に起きており、ID を文字列で返す API が多いのはこれが理由です。
Rust では、整数は整数型で持てば、この問題は起きません。

## 4. 特殊な値: 無限大と NaN

```
1.0 / 0.0  = inf
0.0 / 0.0  = NaN   (Not a Number: 非数)
NaN == NaN → false
```

浮動小数点数の 0 割りは panic しません（整数とは違います）。

**NaN は自分自身とすら等しくない**。これは IEEE 754 で決まっている仕様です。

## 5. ⭐ だから Rust の `f64` は `Eq` も `Ord` も実装していない

Rust の比較トレイトは、数学的な性質を約束するものです。

| トレイト | 約束していること | f64 は守れるか |
|---|---|---|
| `PartialEq` | `==` が使える | ○ |
| `Eq` | 全ての値で `a == a` が成り立つ | × NaN が反例 |
| `PartialOrd` | `<` が使える（ただし比較できない組がありうる） | ○ |
| `Ord` | どの2つの値も必ず大小が決まる | × NaN は何とも比較できない |

その結果、次のようになります。

```rust
let mut v = vec![3.2, 1.5, 2.7];
v.sort();                  // コンパイルエラー: f64 は Ord ではない
v.sort_by(f64::total_cmp); // NaN も含めて順序を定義した比較関数を使う
```

`f64` は `HashMap` のキーにもできません（`Eq` と `Hash` が必要だからです）。
他の言語なら「NaN が混ざると、ソートの結果がおかしくなる」という目に見えにくいバグになるところを、Rust は**型でコンパイル時に止めています**。数学的な性質を型で表すという Rust の考え方の良い例です。
