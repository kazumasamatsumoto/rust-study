# 04. ポインタと、メモリ安全性のバグ

## 1. ポインタとは

**ポインタ**とは、メモリのアドレスを値として持つ変数です。「データそのもの」ではなく「データがどこにあるか」を持っています。

```
     アドレス    値
   ┌──────────┬───────┐
x  │ 0x1000   │  42   │
   ├──────────┼───────┤
p  │ 0x1008   │0x1000 │ ← x のアドレスを持っている
   └──────────┴───────┘
```

Rust の参照 `&x` は、機械語のレベルではただのポインタ（8 バイトのアドレス）です。
違うのは、コンパイラが**「そのポインタが指す先が、ちゃんと生きているか」を検証してくれる**ことだけです。

## 2. ファットポインタ

```
&i32   : 8 バイト   ← アドレスだけ
&str   : 16 バイト  ← アドレス + 長さ
&[i32] : 16 バイト  ← アドレス + 長さ
```

スライスへの参照は、**長さも一緒に持っています**（ファットポインタ）。
そのため Rust では `v[100]` のような範囲外へのアクセスを、実行時に検出して panic にできます。C の配列はアドレスしか持たないので、どこまでが配列なのかを知る手段がなく、範囲外のメモリを黙って読み書きしてしまいます。

## 3. ⭐ メモリ安全性のバグ

C や C++ では、以下のバグがコンパイラを通ってしまいます。Microsoft や Google は、自社製品の深刻な脆弱性のおよそ7割がメモリ安全性の問題だと報告しています。

| バグ | 何が起きるか | Rust が防ぐ仕組み |
|---|---|---|
| **解放後の使用** (use-after-free) | 解放済みのメモリを読み書きする。そこにはもう別のデータがあるかもしれない | 借用チェッカー: 参照は、所有者より長く生きられない |
| **ダングリングポインタ** | 消えたスタックフレームを指し続ける | ライフタイム（Stage 07） |
| **二重解放** (double free) | 同じメモリを2回解放して、アロケータが壊れる | 所有権: 解放の責任を持つのは1人だけ |
| **バッファオーバーフロー** | 配列の範囲外に書き込む | ファットポインタによる範囲チェック |
| **ヌルポインタの参照** | アドレス 0 を読もうとしてクラッシュする | 参照は必ず有効。ないかもしれない場合は `Option` |
| **データ競合** | 複数のスレッドが同時に書き込む | `Send` / `Sync`（Stage 10） |
| **メモリリーク** | 解放し忘れる | 所有者がスコープを抜けると自動で解放される（ただし `Rc` の循環参照などでは起こりうる。リークは「安全でない」とはみなされていない） |

### 例: 解放後の使用

C++ で書くと、次のコードはコンパイルが通ります。

```cpp
std::vector<int> v = {1, 2, 3};
int* first = &v[0];   // v の先頭を指すポインタ
v.push_back(4);       // 容量が足りないので、v のデータは別の場所に移動する
*first = 10;          // 移動前の、解放済みの場所に書き込む → 未定義動作
```

Rust で同じことを書くと、こうなります。

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];
v.push(4);        // コンパイルエラー: v は借用中なので書き換えられない
println!("{first}");
```

Stage 02 で学ぶ借用のルールは、この**「push で中身が移動するかもしれない」という事実**から逆算して作られています。
（中身が本当に移動することは、`vec_growth` の実験で確かめられます。）

## 4. `unsafe`

Rust にも生ポインタ（`*const T`, `*mut T`）があり、`unsafe` ブロックの中でだけ使えます。
`unsafe` は「チェックを無効にする」という意味ではありません。「**コンパイラが検証できないことを、プログラマが代わりに保証する**」という宣言です。

標準ライブラリの `Vec` の中身は `unsafe` を使って書かれていますが、その外側には安全な API だけが公開されています。
「**危険な部分を小さな範囲に閉じ込めて、外には安全なインターフェースだけを見せる**」のが、Rust の設計の基本パターンです。
