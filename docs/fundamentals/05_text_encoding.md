# 05. 文字コードと UTF-8

```bash
cargo run -p fundamentals --example utf8
```

## 1. 文字も数値として保存されている

コンピュータは数値しか扱えません。そのため、文字ごとに番号を決めて保存しています。

- **ASCII**（1963年）: 英数字と記号に 0〜127 の番号を割り当てたもの。'a' = 97 = 0x61。1 バイトに収まります
- **Unicode**: 世界中の文字に番号を割り当てたもの。この番号を**コードポイント**と呼び、`U+3042`（あ）のように書きます。範囲は U+0000〜U+10FFFF です

Unicode は「文字に番号を割り当てる表」にすぎません。**その番号をどうバイト列にするか**（エンコーディング）は、別の問題です。

## 2. UTF-8: 可変長のエンコーディング

UTF-8 は、コードポイントの大きさに応じて **1〜4 バイト**を使います。

```
"a"  → 61           (1バイト)  U+0061
"é"  → C3 A9        (2バイト)  U+00E9
"あ" → E3 81 82     (3バイト)  U+3042
"🦀" → F0 9F A6 80  (4バイト)  U+1F980
```

| コードポイントの範囲 | バイト数 | 主な文字 |
|---|---|---|
| U+0000〜U+007F | 1 | ASCII（英数字） |
| U+0080〜U+07FF | 2 | ラテン文字のアクセント付き文字、ギリシャ文字など |
| U+0800〜U+FFFF | 3 | **日本語のほとんど**、中国語 |
| U+10000〜 | 4 | 絵文字、一部の漢字 |

**UTF-8 が主流になった理由**
- ASCII と互換性がある。英語のテキストは ASCII のときとバイト列が全く同じになります
- 英語中心のテキストでは、サイズが小さくなります
- 先頭のバイトを見るだけで、その文字が何バイトか分かります。文字の途中から読み始めても、次の文字の先頭を見つけられます

**その代わりに払うもの**: 1文字のバイト数が一定ではないので、**n 番目の文字の位置を、計算で求められません**。先頭から順にたどる必要があります。

## 3. ⭐ Rust の文字列 API はこの事実をそのまま表している

```
"Rustは楽しい"
  len() (バイト数) = 16
  chars().count()  = 8
```

| API | 意味 | 計算量 |
|---|---|---|
| `s.len()` | **バイト数** | O(1) |
| `s.chars().count()` | 文字（コードポイント）の数 | O(n) |
| `s[0]` | **コンパイルエラー** | — |
| `&s[0..3]` | バイト位置でのスライス。文字の途中で切ると panic | O(1) |
| `s.get(0..2)` | 同上。ただし失敗したら `None` を返す | O(1) |
| `s.chars().nth(i)` | i 番目の文字 | O(n) |

`len()` が文字数ではなくバイト数を返すのは、それが O(1) で分かる値だからです。
`s[0]` を禁止しているのは、「1バイト目」と「1文字目」のどちらを返すべきかが曖昧で、しかも1文字目を返すには O(n) かかってしまうからです。

**他の言語との比較**
- Python 3: `len("あ") == 1`。内部の表現を工夫して、文字単位でのアクセスを O(1) にしている（その代わり、メモリを多く使うことがある）
- Java / JavaScript: UTF-16。`"🦀".length == 2` のように、**絵文字が2文字として数えられてしまう**
- Go: Rust と同じく UTF-8 で、`len` はバイト数を返す

## 4. `char` は「見た目の1文字」ではない

```
"👨‍👩‍👧"
  len() (バイト数) = 18
  chars().count()  = 5    ← 見た目は1文字なのに5
  コードポイント   = U+1F468 U+200D U+1F469 U+200D U+1F467
```

家族の絵文字は「男性 + 結合文字(ZWJ) + 女性 + ZWJ + 女の子」で作られています。
「見た目の1文字」は**書記素クラスタ**（grapheme cluster）と呼ばれ、それを数えるには `unicode-segmentation` クレートが必要です。

```
"é" と "e\u{301}": 等しい? → false
```

見た目が同じ「é」にも、「é を表す1つのコードポイント」と「e + アクセント記号」の2通りの表し方があります。ユーザーが入力した文字列を比べるときは、**正規化**（`unicode-normalization` クレート）が必要になることがあります。

**教訓**: 「文字数」には少なくとも、バイト数・コードポイントの数・見た目の文字数の3種類があります。仕様に「30文字まで」と書かれていたら、どれのことかを確認しましょう。
