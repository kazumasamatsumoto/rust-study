# 06. 計算量とデータ構造

```bash
cargo run -p fundamentals --example vec_growth --release
```

## 1. 計算量（オーダー記法）

**計算量**は「データが増えたときに、処理時間がどれくらいのペースで増えるか」を表します。

| 記法 | 名前 | データが10倍になると | 例 |
|---|---|---|---|
| O(1) | 定数時間 | 変わらない | `v[i]`, `s.len()` |
| O(log n) | 対数時間 | 少しだけ増える | 二分探索, `BTreeMap::get` |
| O(n) | 線形時間 | 10倍 | `v.contains(&x)`, `s.chars().count()` |
| O(n log n) | | 10倍強 | `v.sort()` |
| O(n²) | 二乗時間 | 100倍 | 二重ループで全ての組を比べる |

細かい係数は無視して、「データが増えたときの伸び方」だけを見ます。データが少ないうちはどれでも速いですが、**データが増えると、オーダーの違いが全てを決めます**。

## 2. ⭐ Vec の push はなぜ速いのか（償却計算量）

```
len=   0 cap=   0
len=   1 cap=   4 移動した
len=   5 cap=   8 移動した
len=   9 cap=  16 移動した
len=  17 cap=  32 移動した
...
len= 513 cap=1024 移動した
```

`Vec` は、容量が足りなくなったときに**約2倍の大きさの領域を確保し直し、中身を全てコピー**します（倍率は実装の詳細で、将来変わる可能性があります）。

コピーには O(n) かかりますが、それが起きるのは**容量が2倍になるときだけ**です。1000 回 push しても、コピーが起きるのは約10回だけです。全体を平均すると、1回の push は O(1) になります。これを**償却 O(1)**と呼びます。

最終的な要素数が分かっている場合は、`Vec::with_capacity(n)` で最初に確保しておけば、コピーを完全になくせます。

そして、ここでも「移動した」と表示されていることに注目してください。**push すると中身の場所が変わる**ことがあります。これが、借用中の Vec に push できない理由でした（04 を参照）。

## 3. 先頭への挿入は遅い

```
push      x50000: 96.75µs
insert(0) x50000: 78.218375ms   ← 約800倍遅い
```

`insert(0, x)` は、既存の全ての要素を1つずつ後ろにずらす必要があるので O(n) です。これを n 回繰り返すと O(n²) になります。
両端への追加と削除が必要なら、`VecDeque`（リングバッファ）を使えば、どちらの端でも O(1) になります。

## 4. 主なデータ構造の計算量

| 操作 | `Vec` | `VecDeque` | `HashMap` | `BTreeMap` |
|---|---|---|---|---|
| インデックス/キーで取得 | O(1) | O(1) | 平均 O(1) | O(log n) |
| 末尾に追加 | 償却 O(1) | 償却 O(1) | — | — |
| 先頭に追加 | O(n) | 償却 O(1) | — | — |
| 挿入 | O(n) | O(n) | 平均 O(1) | O(log n) |
| 値の検索 | O(n) | O(n) | 平均 O(1) | O(log n) |
| 順序 | 挿入順 | 挿入順 | **順序なし** | **キーでソート済み** |

**選ぶ基準**
- 迷ったら `Vec`。メモリ上で連続しているので CPU キャッシュが効きやすく、実際にはオーダー以上に速いことが多いです
- キーで検索したい → `HashMap`
- キーの順番で取り出したい、範囲で検索したい → `BTreeMap`

## 5. 計算量だけでは決まらない

CPU は、メモリから一度にまとまった量のデータをキャッシュに読み込みます。
- `Vec` は要素が**連続して並んでいる**ので、続けて読むときにキャッシュが効きます
- 連結リストは要素が**メモリ上に散らばっている**ので、要素を1つ読むたびにキャッシュミスが起きやすくなります

そのため、理論上は連結リストのほうが有利な操作でも、実際には `Vec` のほうが速いことがよくあります。
Rust の標準ライブラリにも `LinkedList` はありますが、使われることはほとんどありません。**推測するより計測**しましょう（Part 3 で `criterion` を使ったベンチマークを書きます）。
