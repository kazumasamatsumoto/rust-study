# Rust を選ぶべき時・選ぶべきでない時

## Rust の強み

| 強み | 具体的には |
|---|---|
| C/C++ に並ぶ性能 | GC がなく、ゼロコスト抽象化。メモリ使用量が少ない |
| メモリ安全 | 解放後の使用やデータ競合がコンパイル時に防がれる。セキュリティ上の脆弱性が減る |
| 遅延が予測しやすい | GC による一時停止がない。p99 のレイテンシが安定する |
| 変更に強い | 型と網羅性チェックがあるので、大規模なリファクタリングでもコンパイラが漏れを教えてくれる |
| 配布が楽 | 単一のバイナリにでき、ランタイムが不要 |
| 動く場所が広い | CLI、サーバ、WASM、組み込み、OS カーネル |

## Rust の弱み

| 弱み | 具体的には |
|---|---|
| 学習コスト | 所有権、ライフタイム、トレイトを覚える必要がある。チーム全員が習得するには時間がかかる |
| コンパイルが遅い | 大きなプロジェクトではビルドに数分かかることがある |
| 試作が遅い | 「とりあえず動かす」速さでは Python や TypeScript に負ける |
| エコシステムが弱い分野 | GUI、機械学習の学習処理（Python が圧倒的）、一部の業務 SaaS の SDK |
| 採用 | Go や TypeScript に比べて経験者が少ない |

## 実際の採用例と、その理由

- **Discord**: GC による遅延のスパイクが問題になったサービスを、Go から Rust に書き換えた → **遅延の予測しやすさ**
- **Cloudflare (Pingora)**: nginx に代わるプロキシを Rust で作った → **性能とメモリ安全**
- **Linux カーネル / Android / Windows**: Rust の導入を進めている → **メモリ安全性の脆弱性を減らすため**（Google や Microsoft は、深刻な脆弱性の約7割がメモリ安全性に起因すると報告しています）
- **CLI ツール**（ripgrep, fd, uv, ruff など）→ **速度と単一バイナリでの配布**

共通点を見てください。「Rust が流行っているから」ではなく、**具体的な痛み（GC の遅延、脆弱性、速度）があったから**選ばれています。

## 判断のフレームワーク

次のどれかに当てはまるなら、Rust は有力な候補です。

- [ ] 性能やメモリの効率が、ビジネス上の価値に直結する（インフラのコスト、レイテンシの SLA）
- [ ] セキュリティが重要で、信頼できない入力を扱う（パーサ、ネットワーク）
- [ ] 長期間保守し、正しさが重要
- [ ] 単一のバイナリで配布したい（CLI、エージェント）
- [ ] WASM や組み込みなど、GC 言語が使いにくい環境

次のどれかに当てはまるなら、他の言語を検討しましょう。

- [ ] 仕様が固まっておらず、とにかく速く試したい → Python / TypeScript
- [ ] 典型的な CRUD の Web アプリで、チームが Rust に慣れていない → TypeScript / Go
- [ ] データ分析や機械学習の実験 → Python
- [ ] チームの大半が Rust を書けず、習得する時間も取れない

> **注意**: 「Rust で書けば速い」は半分しか正しくありません。ボトルネックが DB や外部 API の I/O にあるなら、言語を変えても速くなりません。**まず計測すること。**
