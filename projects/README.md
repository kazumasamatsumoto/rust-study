# Part 3: プロジェクト

ここからは課題の `todo!()` はありません。**要件だけ**が渡されます。
設計、クレートの選定、テストの書き方は、全て自分で決めます。

## 進め方

1. `SPEC.md`（要件）を読む
2. **コードを書く前に**、主な判断について ADR を書く（`docs/adr/` に置く。テンプレートは [docs/judgment/03_adr.md](../docs/judgment/03_adr.md)）
3. マイルストーンごとに PR を作り、Claude にレビューを頼む
4. 完成したら `README.md` を書く（使い方、設計の概要、苦労した点）

## プロジェクトを始めるとき

各プロジェクトは、このワークスペースの中のクレートとして作ります。

```bash
cargo new projects/p01_logscope   # バイナリクレート
# ルートの Cargo.toml の members に "projects/*" を追加する
```

## 評価の観点

Claude がレビューするときは、次の観点で見ます。動くことは前提です。

| 観点 | 見ること |
|---|---|
| 設計 | モジュールの分け方、型の設計、責務の分離 |
| エラー処理 | ユーザーに分かるエラーメッセージか、`unwrap` に頼っていないか |
| テスト | 重要なロジックがテストされているか、テストしやすい設計か |
| 技術選定 | ADR で根拠を説明できているか、他の選択肢と比べているか |
| 性能 | 計測してから最適化しているか（推測で最適化していないか） |
| 運用 | ログ、設定、ヘルプなど、実際に使う人のことを考えているか |
