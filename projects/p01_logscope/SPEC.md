# p01: logscope — ログファイル解析 CLI

## 背景

Web サーバのアクセスログから「どのパスが遅いのか」「エラーはどれくらい出ているのか」を素早く知りたい。
`grep` と `awk` を組み合わせても調べられるが、毎回コマンドを書くのは面倒なので、専用のツールを作る。

## 入力

1行に1リクエストのログ。形式は次のとおり（空白区切り）。

```
2026-11-01T10:00:00Z GET /api/users 200 35ms
2026-11-01T10:00:01Z POST /api/orders 500 1203ms
2026-11-01T10:00:01Z GET /health 200 1ms
```

`時刻 メソッド パス ステータスコード 処理時間`

- 形式が壊れている行もありうる。その場合でも処理を止めず、最後に「何行スキップしたか」を報告する
- ファイルは数GBになることがある。**全体をメモリに読み込まないこと**
- ファイルを指定しない場合は、標準入力から読む（`cat access.log | logscope summary`）

## 機能（マイルストーン）

### M1: 集計
```
logscope summary access.log
```
- 総リクエスト数、ステータスコードの種類ごとの件数（2xx/3xx/4xx/5xx）、スキップした行の数

### M2: パスごとの統計
```
logscope paths access.log --sort p95 --top 10
```
- パスごとの件数、平均・中央値・p95・最大の処理時間
- `--sort` で並び替えるキーを、`--top` で表示する件数を指定できる
- 考えること: p95 を正確に求めるには、全ての値を持っておく必要がある。メモリと正確さのトレードオフをどうするか（ADR に書く）

### M3: フィルタ
```
logscope paths access.log --status 5xx --since 2026-11-01T10:00:00Z --method POST
```

### M4: 出力形式
- `--format table`（デフォルト。人が読む用）/ `--format json`（他のツールに渡す用）

## 非機能要件

- 1GB のログを、release ビルドで10秒以内に処理できること（テスト用のログを生成するスクリプトも自分で用意する）
- エラーメッセージは、ユーザーが次に何をすべきか分かる内容にする（例: ファイルが存在しない場合）
- `--help` が充実していること

## 必須の ADR

1. CLI の引数解析をどうするか（clap / lexopt / 手書き）
2. エラー型の方針（anyhow / thiserror / 独自の型、またはその組み合わせ）
3. パーセンタイルの計算方法（全件保持 / 近似アルゴリズム）
4. 出力形式の実装方法（trait で抽象化するか、enum で分岐するか）— s03 と s06 で学んだ Expression Problem を思い出すこと

## ヒント（詰まったら読む）

<details>
<summary>大きなファイルを読む</summary>

`std::io::BufReader` と `lines()` を調べる。ただし `lines()` は1行ごとに `String` を確保する。性能が足りないときは `read_line` で同じバッファを使い回す方法を検討する。まずは計測すること。
</details>

<details>
<summary>パース処理をテストしやすくする</summary>

ファイル I/O とパース処理を分ける。パースは `&str` を受け取って `Result<LogEntry, ParseError>` を返す純粋な関数にすると、テストが簡単になる。入力元を `impl BufRead` で受け取れば、テストでは `&[u8]` を渡せる。
</details>
